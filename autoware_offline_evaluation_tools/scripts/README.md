# OR Scene Evaluation Scripts

This directory contains scripts to run DLR simulations and OR scene evaluations for trajectory planning analysis.

## Available Scripts

### 1. `run_dlr.sh` - Run DLR Simulation Only

Runs driving_log_replayer_v2 simulation to generate LIVE trajectory data.

**Usage:**
```bash
./run_dlr.sh <scenario_path>
```

**Example:**
```bash
./run_dlr.sh /media/external_drive/t4_dataset/scenario.yaml
```

**Output:**
- DLR results in `<dataset_dir>/out/latest/`
- Result bag: `<dataset_dir>/out/latest/result_bag/result_bag_0.mcap`

---

### 2. `run_evaluation.sh` - Run Evaluation Only

Evaluates existing DLR results without re-running simulation.

**Usage:**
```bash
./run_evaluation.sh <result_bag_path> <input_bag_path> <trajectory_topic> <output_dir>
```

**Arguments:**
- `result_bag_path` - Path to DLR result_bag_0.mcap (contains LIVE trajectories)
- `input_bag_path` - Path to input bag directory (for OR event extraction)
- `trajectory_topic` - Full trajectory topic name to evaluate
- `output_dir` - Directory for outputs (will be created if doesn't exist)

**Example:**
```bash
./run_evaluation.sh \
  /media/external_drive/t4_dataset/out/latest/result_bag/result_bag_0.mcap \
  /media/external_drive/t4_dataset/input_bag \
  /planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  /media/external_drive/t4_dataset/evaluation_results
```

**Output:**
- `<output_dir>/or_results.json` - Metrics and per-event statistics
- `<output_dir>/or_debug_images/` - Visualization PNG files
- `<output_dir>/evaluation_output.bag/` - Evaluation metrics as rosbag

---

### 3. `run_dlr_and_evaluate.sh` - Complete Pipeline

Runs DLR simulation followed by automatic evaluation. Cleans up previous outputs.

**Usage:**
```bash
./run_dlr_and_evaluate.sh <scenario_path> <trajectory_topic> <output_dir>
```

**Arguments:**
- `scenario_path` - Path to T4 dataset scenario.yaml
- `trajectory_topic` - Trajectory topic to evaluate
- `output_dir` - Directory for evaluation outputs

**Example:**
```bash
./run_dlr_and_evaluate.sh \
  /media/external_drive/t4_dataset/scenario.yaml \
  /planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  /media/external_drive/t4_dataset/evaluation_results
```

**Output:**
- DLR results in `<dataset_dir>/out/latest/`
- Evaluation results in `<output_dir>/`
- Displays metrics summary at completion

## Common Trajectory Topics

Different planners use different topic names:

| Planner | Topic Name |
|---------|------------|
| Diffusion Planner | `/planning/trajectory_generator/diffusion_planner_node/output/trajectory` |
| Trajectory Optimizer | `/planning/trajectory_generator/trajectory_optimizer_node/output/trajectory` |
| Standard Planning | `/planning/trajectory` or `/planning/scenario_planning/trajectory` |

**Tip:** Use `ros2 bag info <bag_path>` to list all available topics in a bag.

## T4 Dataset Structure

All scripts expect the T4 dataset format:

```
t4_dataset/
├── annotation/
├── data/
│   └── LIDAR_CONCAT/
├── input_bag/
│   ├── *.db3          # Rosbag file(s)
│   └── metadata.yaml  # Generated by ros2 bag reindex
├── map/               # Symlink or directory
│   ├── lanelet2_map.osm
│   └── pointcloud_map.pcd
├── scenario.yaml      # DLR scenario configuration
└── out/              # Created by DLR
    └── latest/       # Symlink to most recent run
        └── result_bag/
            └── result_bag_0.mcap
```

## Preparing a T4 Dataset

### Step 1: Download Rosbag

```bash
webauto data rosbag pull \
  --project-id prd_jt \
  --environment-id <env-id> \
  --rosbag-id <rosbag-id>
```

### Step 2: Create Directory Structure

```bash
mkdir -p ~/t4_dataset/my_test/{annotation,data/LIDAR_CONCAT,input_bag}
```

### Step 3: Copy and Reindex Rosbag

```bash
# Copy rosbag to input_bag/
cp ~/.webauto/data/data/rosbag/<id>/*.db3 ~/t4_dataset/my_test/input_bag/

# Reindex to create metadata.yaml
cd ~/t4_dataset/my_test/input_bag
source ~/pilot-auto/install/setup.bash
ros2 bag reindex -s sqlite3 .
```

### Step 4: Link Map

```bash
ln -s ~/autoware_map/shinagawa_odaiba_stable ~/t4_dataset/my_test/map
```

### Step 5: Create scenario.yaml

```yaml
ScenarioFormatVersion: 3.0.0
ScenarioName: my_test
ScenarioDescription: Test scenario
SensorModel: aip_xx1
VehicleModel: lexus
publish_profile: planning_control
Evaluation:
  UseCaseName: planning_control
  UseCaseFormatVersion: 2.0.0
  Datasets:
    - ./:
        VehicleId: default
  Conditions:
    ControlConditions: null
```

**CRITICAL:** Include `publish_profile: planning_control` to prevent historical trajectory replay.

## Workflow Examples

### Example 1: Full Pipeline

```bash
# Run DLR and evaluate in one command
./run_dlr_and_evaluate.sh \
  ~/t4_dataset/my_test/scenario.yaml \
  /planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  ~/t4_dataset/my_test/results
```

### Example 2: Separate Steps

```bash
# Step 1: Run DLR only
./run_dlr.sh ~/t4_dataset/my_test/scenario.yaml

# Step 2: Evaluate results later
./run_evaluation.sh \
  ~/t4_dataset/my_test/out/latest/result_bag/result_bag_0.mcap \
  ~/t4_dataset/my_test/input_bag \
  /planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  ~/t4_dataset/my_test/results
```

### Example 3: Compare LIVE vs HISTORICAL

```bash
# Evaluate LIVE (from result_bag)
./run_evaluation.sh \
  ~/t4_dataset/my_test/out/latest/result_bag/result_bag_0.mcap \
  ~/t4_dataset/my_test/input_bag \
  /planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  ~/t4_dataset/my_test/results_live

# Evaluate HISTORICAL (from input_bag)
ros2 run autoware_offline_evaluation_tools offline_evaluator_node --ros-args \
  -p bag_path:=~/t4_dataset/my_test/input_bag \
  -p evaluation.mode:=or_scene \
  -p trajectory_topic:=/planning/trajectory_generator/diffusion_planner_node/output/trajectory \
  -p or_scene_evaluation.evaluate_live_trajectories:=false \
  -p or_scene_evaluation.enable_debug_visualization:=true \
  -p or_scene_evaluation.debug_output_dir:=~/t4_dataset/my_test/results_historical/images \
  -p json_output_path:=~/t4_dataset/my_test/results_historical/or_results.json

# Compare metrics
diff <(cat ~/t4_dataset/my_test/results_live/or_results.json | grep mean_ade) \
     <(cat ~/t4_dataset/my_test/results_historical/or_results.json | grep mean_ade)
```

## Understanding Results

### JSON Output Structure

The evaluation generates a JSON file with three levels of aggregation:

1. **Per-trajectory**: Individual predictions with ADE, FDE, TTC, coverage
2. **Per-OR-event**: Aggregated metrics for all predictions around one override
3. **Summary**: Overall statistics across all OR events

**Key Metrics:**
- `ade` - Average Displacement Error (mean distance between predicted and actual path)
- `fde` - Final Displacement Error (distance at trajectory endpoint)
- `mean_lateral_deviation` - Lateral error in vehicle frame
- `min_ttc` - Minimum time to collision with objects
- `gt_coverage_ratio` - Fraction of trajectory with available ground truth

### Visualization Images

Each PNG shows:
- **Green solid line** - Ground truth (actual vehicle path)
- **Blue dashed line** - Predicted trajectory
- **Red star** - Override event location
- **Colored boxes** - Detected objects (cyan=CAR, orange=TRUCK, etc.)
- **Metrics overlay** - ADE, FDE, lateral deviation, TTC, speed, object count

Files are named: `or_event_<id>_pred_<timestamp>.png`

## Troubleshooting

### "No storage could be initialized"

The input bag needs a `metadata.yaml` file. Run:
```bash
cd /path/to/input_bag
source ~/pilot-auto/install/setup.bash
ros2 bag reindex -s sqlite3 .
```

### "Database directory already exists"

The evaluation output path already exists. Either:
- Delete it: `rm -rf /path/to/evaluation_output.bag`
- Use a different output path in the script

### "Failed to lookup element with id"

This warning is normal and can be ignored. It relates to map route lookups and doesn't affect OR scene evaluation.

### No Trajectories Found

Check that:
1. DLR's `publish_profile: planning_control` is set in scenario.yaml
2. Planning nodes actually ran during DLR (check DLR logs)
3. Correct trajectory topic name is specified
4. Result bag exists and contains trajectory data

### Very Long Evaluation Time

OR scene evaluation loads the entire bag for each OR event to generate ground truth. For long bags (>5 minutes), this can take several minutes per OR event. This is expected behavior.

## Performance Tips

1. **Use SSD/fast storage** for bags and outputs (evaluation is I/O intensive)
2. **Pre-extract OR events** to avoid re-extraction on each run:
   ```bash
   # Extract once
   ros2 run autoware_offline_evaluation_tools offline_evaluator_node --ros-args \
     -p bag_path:=/path/to/input_bag \
     -p evaluation.mode:=or_scene \
     -p or_scene_evaluation.or_events_output_path:=/path/to/or_events.json

   # Reuse in future evaluations
   -p or_scene_evaluation.skip_or_extraction:=true \
   -p or_scene_evaluation.or_events_input_path:=/path/to/or_events.json
   ```

3. **Disable visualization** for faster evaluation if images aren't needed:
   ```bash
   -p or_scene_evaluation.enable_debug_visualization:=false
   ```

## Advanced Usage

### Custom Time Window

Change the evaluation window around OR events (default ±0.5s):
```bash
-p or_scene_evaluation.time_window_sec:=1.0  # ±1 second window
```

### Success Criteria

Enable pass/fail criteria:
```bash
-p or_scene_evaluation.success_criteria.enabled:=true \
-p or_scene_evaluation.success_criteria.max_ade:=1.0 \
-p or_scene_evaluation.success_criteria.max_fde:=1.5 \
-p or_scene_evaluation.success_criteria.min_ttc:=3.0
```

### Different Evaluation Modes

```bash
# Open loop - prediction accuracy
-p evaluation.mode:=open_loop

# Closed loop - trajectory tracking
-p evaluation.mode:=closed_loop

# OR scene - override regression
-p evaluation.mode:=or_scene
```
